# 三档执行流程

## 档位总览

| 深度档 | 字数 | 流程 | 自检 | 适用 |
|---|---|---|---|---|
| **D1 轻写入** | **800-1500** | 0→1(简)→2→3→4(简) | L1 + L5 快扫 | 热点跟进、短评、临时补位 |
| **D2 标准** | **1500-2500** | 0→1→2→3→4→5 | L1 + L2 + L4 + L5 | 日常更新 |
| **D3 深度（默认）** | **2500-4000** | **0→1(横纵)→2(骨架)→3→4(五层)→5(多轮)→6** | **五层全跑** | 重点文章、教程、品牌文 |

**默认 D3，但必须在动笔前跟用户确认。** 用户说「短一点」「先来个初稿」就降档。

> ⚠️ **两套编号不要混用**：写作深度是 **D1/D2/D3**（Depth），自检层级是 **L1-L5**（Layer）。说到「L3」时指的是自检第三层，不是深度档。

---

## D1 轻写入

适用：热点跟进、短评、临时补位。

1. **Phase 0**：判定类型，写下风格锚点。
2. **Phase 1（简）**：只做一件事——确认核心事实，搜一次核实关键数字。不做横纵分析。
3. **Phase 2**：内化骨架，一步成文。不先写小标题序列。
4. **Phase 3**：生成 3 个标题，跑标题三问。
5. **Phase 4（简）**：只跑 L1 硬性规则扫描 + L4 活人感快速通读。
6. 输出：正文 + 信心行（`信心 ⭐⭐⭐⭐⭐/5 | 字数 ✅/{N} | 数据 深/中/浅`）。

不生成长报告，不自动进 Phase 6。

---

## D2 标准档

1. **Phase 0** 判定类型 → 风格锚点。
2. **Phase 1** 轻量横纵：纵轴问「这事的来龙去脉」，横轴问「同类还有谁」。各搜一轮。
3. **Phase 2** 先定小标题序列（3-5 节），每节写一句核心判断，确认后再填肉。
4. **Phase 3** 生成 3-5 个标题候选。
5. **Phase 4** 跑 L1 + L2 + L4。
6. **Phase 5** 靶向修改 1 轮。
7. 输出：正文 + 简版质检摘要。

## D3 深度档（默认）

### Phase 0 · 类型判定与锚点

判定 A/B/C/D 四类（见主 SKILL.md），写下**风格锚点**：

```text
[A型·迪谱学长·核心判断：15字以内]
```

**锚点是地基，上面的楼再怎么盖都不能动地基。** 写到一半迷路了、核心判断漂移了，回来对一下这行。

#### HKR 选题质检（D2/D3 必做，D1 可跳过）

锚点写好后，过一遍三个维度：

| 维度 | 问的是 |
|---|---|
| **H**appy（趣味/悬念） | 标题和开头能让人好奇点进来吗？ |
| **K**nowledge（信息增量） | 读完能带走别人没说过的东西吗？ |
| **R**esonance（情绪共鸣） | 能触发「我也是」的共鸣或行动欲吗？ |

- **S 级**：H✅ K✅ R✅
- **合格**：至少两项命中
- **不合格**：只中一项 → **跟用户聊方向再动笔**

#### A 型专属：升番叙事弧

工具实测型用**升番逻辑**推动情绪，不要平铺：

```
悬念引入 → 第一个展示（基础款，建立基线）
→ 第二个展示（升级款，拉开差距）→ 第三个展示（炸裂款，高潮）
→ 翻车/局限 → 适用人群
```

多工具对比时，按「弱 → 强 → 炸」的顺序排，情绪才递进。第一个工具的作用是**建立基线**，不是主角。

### Phase 1 · 横纵选题与素材（本档核心）

这一步决定文章的上限。融合横纵分析法（HV Analysis）。

#### 纵轴（Diachronic）· 时间线

回答「这东西是怎么走到今天的」：

- 它是什么时候出现的，当时的形态是什么
- 中间经历了哪几个关键节点（版本、融资、转型、舆论反转）
- **我是什么时候开始接触的，当时的第一反应是什么**
- 我踩过哪些坑，什么时候开始顺手的
- 现在处在什么阶段（早期/成熟/过热/退潮）

**纵轴的价值是真实感**。尤其是「我什么时候开始用的」这一条——这是 AI 编不出来的部分，也是迪谱学长区别于纯资讯号的壁垒。

如果某个环节自己确实没经历过，如实说「这个阶段我没赶上，看到的情况是……」，不要编。

#### 横轴（Synchronic）· 竞品切面

回答「同样的事还有谁在做，各自什么位子」：

- 同赛道有哪 3-5 个代表（工具/方法/公司）
- 各自解决什么具体问题，不解决什么
- 价格、门槛、适用人群
- 真实口碑和用户吐槽
- 为什么有的火有的没火

**横轴的价值是判断力**。读者要的不是信息罗列，是「那我该选哪个」。

#### 横纵交汇 · 得出增量判断

把两条轴合起来，输出 1-3 个别人没说过的判断。模板：

> 大家都说 X 好，但从纵轴看它才做了 N 个月，稳定性还没验证；横轴比下来，从团队上手成本看，Y 更容易落地。

这个判断就是文章的核心主张，会变成标题和金句。

#### 搜索执行

- 派子 Agent 并行搜：一个搜纵轴（历史、演进、个人经历佐证），一个搜横轴（竞品、对比、口碑）。
- 来源优先级：官方一手 > 权威媒体原创 > 转载聚合。
- 搜不到就标注「暂缺」，绝不编造。
- 硬数字（价格、star 数、用户量、耗时）必须有来源，否则不用或标「未核实」。

#### 研究深度标记

| 标记 | 条件 |
|---|---|
| 深 | 3+ 独立来源，含至少 1 个硬数字 |
| 中 | 1-2 个来源，或只有软数字 |
| 浅 | 未搜、来源单薄、关键数据不可核验 |

深度为「浅」时，文章里不要用断言式表述，改用「我看到的情况是」。

### Phase 2 · 骨架先行

**不要直接写正文。** 先输出骨架给用户确认（或直接内部确认后继续）：

```markdown
# 暂定标题

核心判断：[一句话]

## 小标题一
- 核心判断：
- 支撑素材：
- 金句方向：

## 小标题二
...
```

骨架检查：
- 小标题是判断句/悬念句，不是名词短语
- 每节只有一个核心判断
- 节与节之间有推进关系（事实→拆解→对比→落地），不是平行罗列
- 全文有一个明确的情绪高潮位置

骨架定了再填肉。填肉时不改骨架。

### Phase 3 · 标题

生成 5 个候选，覆盖不同路子：

1. 数字具体化：`6 种方法全整理`
2. 悬念留白：`门槛已经变了...`
3. 反预期：`一个被严重低估的...`
4. 第一人称成果：`我用一个下午把 XX 跑通了`
5. 提问：`谁来兜底安全？`

**硬限制：≤ 64 字节（约 21 个中文字符）。** 生成后逐个数一遍，超了就砍。

跑标题三问（见主 SKILL.md Phase 3）。

### Phase 4 · 五层自检

读 `references/self-check.md`，五层全跑，输出质检报告。**L5（去 AI 味终检）得分 ≥42 才放行。**

### Phase 5 · 多轮修改

最多 3 轮。每轮按优先级改：
核心判断 → 解释系统 → 标题方向 → 结构推进 → 段落表达 → 字词润色。

3 轮后仍有 P0 问题，输出阻断报告交给用户决策，不要自己硬凑。

### Phase 6 · 发布

读 `references/publish.md`。

L3 交付完整发布包：
- 正文 markdown
- 3-5 个标题候选 + 推荐 1 个
- 摘要（≤ 120 字，微信 digest）
- 封面 brief（给 ImageGen 的提示词方向）
- 朋友圈/社群转发文案 1 条
- 质检报告
- 微信内联 HTML（转换后）

## 通用规则

### 字数控制

| 档位 | 目标 | 下限 | 上限 |
|---|---|---|---|
| L1 | 1200 | 800 | 1500 |
| L2 | 2000 | 1500 | 2500 |
| L3 | 3200 | 2500 | 4000 |

统计中文字数（不含标点和空格）。低于下限说明展开不够，高于上限说明有冗余观点，砍掉一个次级论点，不要压缩已有内容。

### 素材不足时的处理

如果搜不到足够素材，或用户只给了一个主题没有其他信息：

1. 先问用户要真实经历（工具实测类尤其）：「这个工具你自己用过吗？第一次用是什么感受？卡在哪了？」
2. 用户也没有，就降级为「我看到的情况是」视角，明确标注不是实测。
3. 绝不为了凑字数编造细节。

**AI 的角色边界**（继承自 Khazix Writer）：

| 交给 AI | 必须人来 |
|---|---|
| 找证据和佐证、历史/学术参照 | 第一手观察和真实经历 |
| 找类比和比喻 | 核心创意角度 |
| 补充背景知识（准确表述概念） | 情绪的真实表达 |
| 按确定角度扩写 | 数据到人物的同理心转换 |
| 逻辑和结构建议 | 最终判断和定稿 |
