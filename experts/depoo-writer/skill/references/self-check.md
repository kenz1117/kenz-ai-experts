# 五层自检体系（L1-L5）

设计思路来自软件工程的测试金字塔：从硬性规则到主观活人感，层层递进。**五层全过才算达标**。

D3 档**五层全跑**并输出报告（L5 需 ≥42 分）。D2 跑 L1+L2+L4+L5。D1 只跑 L1 + L5 快扫。

---

## L1 硬性规则（自动扫描层）

违反即修复，没有例外。可以用 grep 扫。

```bash
# 禁用词扫描
grep -nE "说白了|意味着什么|这意味着|本质上|换句话说|不可否认|综上所述|总的来说|值得注意的是|不难发现|让我们来看看|接下来让我们|首先.*其次.*最后" 文章.md

# 教科书开头
grep -nE "^在当(今|下)|随着.*的发展|在当今.*时代" 文章.md

# 绝对化表述
grep -nE "最好的|唯一(的)?选择|彻底颠覆|完美解决|100%|一定能" 文章.md

# 空泛工具名
grep -nE "某(个)?AI工具|相关(产品|技术)|这个模型|某平台" 文章.md
```

### L1-1 禁用词

命中即替换：

| 禁用词 | 替换为 |
|---|---|
| 说白了 | 坦率讲 / 其实就是 |
| 意味着什么 / 这意味着 | 那结果会怎样呢 / 所以呢 |
| 本质上 | 说到底 / 其实 |
| 换句话说 | 你想想看 / 也就是说 |
| 不可否认 | 删掉，正面陈述 |
| 综上所述 / 总的来说 | 换成具体回扣句 |
| 首先…其次…最后 | 用「第一、第二、第三」写在段落里 |
| 值得注意的是 / 不难发现 | 删掉，直接说 |
| 赋能 | 除非调侃企业黑话，否则换成「帮 XX 做到 XX」 |

### L1-2 事实核验

- 每个硬数字（价格、star 数、用户量、耗时、百分比）是否可核验？
- 不可核验的：要么删，要么标注「据官方数据」「我看到的情况是」
- 版本号、发布时间是否准确？
- 对比类断言（「比 XX 快 3 倍」）是否有来源？

### L1-3 工具名具体化

所有提到的工具必须是具体名称（Claude Code、Codex、Kimi、豆包、飞书多维表格……），不能出现「某 AI 工具」「相关产品」。

### L1-4 标题长度

```bash
# 标题字节数（微信上限 64 字节）
python3 -c "print(len('你的标题'.encode('utf-8')))"
```

超过 64 字节必须砍。

### L1-5 编造检测（本 skill 专属红线）

逐条自问：

- 写到的每一个「我用过」的工具，是真的用过吗？
- 每一个具体时间、数字、对话，是真实的吗？
- 每一个案例人物，是真有其事还是编的？

任何一条答不上来，改成不确定表述或删掉。

**通过标准**：以上五项零命中或已全部修复。

## L2 迪谱学长文风一致性（模式匹配层）

### L2-1 开场三件套

```bash
head -8 文章.md
```

必须是：
```markdown
# [标题]

这是迪谱学长的第 N 篇原创！

大家好，我是迪谱学长。
```

检查：N 是否与 `assets/serial.txt` 一致（开场时读取）。

### L2-2 段落节奏

- [ ] 随机抽 10 段，超过 4 段是 40 字以上长句 → 不合格，切开
- [ ] 单句成段出现 ≥ 8 处
- [ ] 没有超过 100 字的段落
- [ ] 长句后跟了短句

```bash
# 找出超长段落
awk 'length($0)>100 {print NR": "length($0)}' 文章.md
```

### L2-3 小标题

- [ ] 用了 `##` 小标题（3-5 个）
- [ ] 小标题是判断句/悬念句/口语化地标，不是名词短语
- [ ] 没有报告式标题（「一、XX分析」）

### L2-4 金句

- [ ] 加粗 + 「」+ 独立成段的金句 3-5 处
- [ ] 金句可独立成立，不是段落总结句
- [ ] 没有超过 40 字的加粗块

```bash
grep -nE '^\*\*「.*」\*\*$' 文章.md
```

### L2-5 口语化

- [ ] 使用了 ≥ 6 个不同的口头禅（见主 SKILL.md 弹药库）
- [ ] 有至少 1 处自嘲或承认不足
- [ ] 有至少 1 处设问单独成段
- [ ] 有至少 1 处排比递进

### L2-6 反鸡汤（本号最值钱的动作）

- [ ] 正面结论之后，有没有主动拆解它的局限性？
- [ ] 有没有承认运气、时机、局限？
- [ ] 结尾是不是在最高处直接停了？（是则不合格，需要降温段）

### L2-7 图片与引用块

- [ ] 每 3-6 段有图（或图占位）
- [ ] 链接、补充、成本说明放在 `>` 引用块里
- [ ] 正文观点没有塞在引用块里

**通过标准**：L2-1 必须过；L2-2 至 L2-7 至少过 5 项。

## L3 内容质量（深度审查层）

### L3-1 观点支撑

- 每个核心判断后面，是否跟了具体的人/场景/细节/数据？
- 有没有只有论断没有例证的段落？

### L3-2 人话翻译（迪谱学长专属，最重要）

本号读者默认不是技术人。逐项检查：

- 出现的每个技术名词（API、RAG、微调、上下文、Token、Agent、MCP、提示词工程……）是否紧跟了一句人话解释？
- 解释是否用了类比？（「就像……」）
- 有没有连续 3 个以上术语没有解释？
- **有没有出现翻译宣告**：「翻译成人话」「说人话」「用人话说」「简单说，它就是」——出现即删，改成直接给类比或场景

```bash
# 翻译宣告检查（应为 0 命中）
grep -nE "翻译成人话|说人话|用人话说|简单说，它就是" 文章.md
```

**检查方法**：把文章给一个完全不懂 AI 的人读，标出他卡住的地方。

```bash
# 术语密度检查
grep -oE "API|RAG|Agent|MCP|Token|微调|提示词|上下文|多模态|大模型|部署|Prompt" 文章.md | sort | uniq -c | sort -rn
```

高频术语如果前后 100 字内没有解释，就是术语墙。

### L3-3 横纵深度

- 纵轴：有没有时间线？有没有「我什么时候开始用」的真实经历？
- 横轴：有没有同赛道对比？对比维度是否包含价格、门槛、适用人群？
- 交汇：有没有得出别人没说过的判断？还是只是信息罗列？

### L3-4 落地可执行（B/C 类必查）

- 每一节读者读完，手里有没有一个今天下午就能做的动作？
- 有没有说明学习成本、时间曲线、常见失败点？
- 有没有只画饼不给路径的地方？

### L3-5 企业视角（C 类必查）

- 有没有落到具体场景（哪个岗位、哪段流程）？
- 有没有算账（省多少时间/钱，投入多少）？
- 有没有谈落地阻力（员工不会用、数据不敢上、老板看不到效果）？
- 有没有回避 ROI？

### L3-6 反鸡汤与边界

- 有没有绝对化表述？
- 有没有把类比当论证？
- 有没有承认这个方案的适用边界（不适合谁）？

### L3-7 结构推进

- 节与节之间是推进关系还是平行罗列？
- 有没有偏离主线后没拉回来的段落？
- 情绪高潮在哪？高潮后有没有降温？

**通过标准**：L3-1、L3-2 必须过；其余按文章类型选择适用项，至少过 2/3。

## L4 活人感终审（最终人格层）

这一层不做逐项打勾，而是通读全文回答一个问题：

> **读完这篇文章，我感觉是一个真把 AI 用过的人（踩过坑、算过账）在跟我掏心窝子，还是一个 AI 在给我输出信息？**

### L4-1 温度感

- 情绪表达是体感记忆还是知识性描述？

  | 体感记忆（要） | 知识性描述（不要） |
  |---|---|
  | 我当时就愣住了 | 我感到非常震撼 |
  | 盯着后台看了半天没敢信 | 数据表现超出预期 |
  | 试了一下午没跑通，差点放弃了 | 实施过程中遇到了一些挑战 |

### L4-2 独特性

- 这篇文章有没有「只有迪谱学长才会写出来的角度」？
- 换一个 AI 博主写，会不会写出差不多的东西？（是则不合格）
- 有没有属于个人的、不可复制的细节？

### L4-3 姿态

- 是「一个早走几步的学长在分享踩坑经验」，还是滑进了「导师在教学生」「品牌在做营销」？
- 有没有居高临下的点评？
- 有没有为了显得专业而堆术语？

### L4-4 心流

从头到尾读一遍，标出注意力断掉的地方。断掉通常因为：
- 逻辑跳跃，缺过渡
- 突然插入一段背景知识打断叙事
- 一段超过 100 字
- 抽象概念出现得太早

### L4-5 冷读（D3 档执行）

把文章当作第一次看到，回答三个问题：
1. 标题会让你点开吗？
2. 前三段会让你继续读吗？
3. 读完你会想转发吗？为什么？

**通过标准**：L4-1 到 L4-4 整体感觉「这是真人写的」。任何一项觉得 AI 味重，就返工。

**修复方法**：这层没有机械修法。找到 AI 味重的段落，想象自己正跟一个想用 AI 却不知从何下手的朋友喝酒聊天，用那个语气重写。

## L5 去 AI 味终检（发布前最后一道关）

读 `references/ai-flavor-check.md`，做三件事：

1. **扫 24 种 AI 模式**（A 内容 / B 语言 / C 风格 / D 交流 四组）
2. **跑灵魂检查**（去完痕还要有魂）
3. **打 50 分质量分**

> ⚠️ **注意豁免**：humanizer 有 5 条规则与本号文风冲突（金句、粗体、破折号、三段式、否定式排比），已在终检文件「零、冲突豁免」中标注。**冲突时以本号文风为准**——不要为了去 AI 味，把金句和排比删掉。

### L5-1 金句万能测试（最重要）

逐条检查每处金句：

> **抽出来，能原封不动套到任何一篇 AI 文章上吗？**

- 能 → 万能金句，重写成只对这篇成立
- 不能 → 专属金句，保留

### L5-2 评分与放行

| 得分 | 处理 |
|---|---|
| **≥42** | 合格，可发布 |
| 35-41 | 按快速清单修一遍 |
| <35 | AI 味重，返工重写 |

**通过标准**：≥42 分，且 A 组（内容模式）零命中。

**快速自检命令**：

```bash
# AI 高频词（应为 0 命中）
grep -nE "此外|至关重要|深入探讨|持久的|培养|格局|织锦|宝贵的|充满活力|标志着|见证了|不可磨灭" 文章.md

# 粗体数量（应 ≤5）
grep -cE '^\*\*「.*」\*\*$' 文章.md

# 破折号数量（应 ≤3）
grep -o '——' 文章.md | wc -l
```
