# 六维评分规则与质量标准

---

## 评分模型

总分 = Σ(维度 score × weight)，0-100 整数。
评级：≥90 优秀 / ≥75 良好 / ≥60 一般 / <60 较差

| code | 名称 | 权重 | fallback（数据缺失时） |
|------|:--:|:--:|:--:|
| `RETRIEVABILITY` | 检索可见度 | 0.25 | 40 |
| `AUTHORITY` | 权威与背书 | 0.20 | 35 |
| `CONTENT_ASSETS` | 内容资产 | 0.15 | 40 |
| `STRUCTURE_MARKUP` | 结构化与标记 | 0.15 | 30 |
| `SENTIMENT` | 舆情健康 | 0.15 | 70 |
| `COMPETITIVE` | 竞争位势 | 0.10 | 50 |

> fallback 是**保守估计**，不是中性值。缺失维度用 fallback 填充后，报告会打「数据缺失」角标。

---

## 锚定表

评分必须落在对应区间内，只允许 ±5 分微调。微调依据写在 comment 里。

### RETRIEVABILITY 检索可见度

| 条件 | 区间 |
|------|:--:|
| 通用词命中率 ≥ 0.5 | 80-95 |
| 通用词命中率 ≥ 0.3 | 65-79 |
| 通用词命中率 ≥ 0.15 | 45-64 |
| 通用词命中率 < 0.15 | 20-44 |

**修正规则**：若命中全部来自含品牌词的查询，下调一档。
只在品牌词查询里出现 = 没有破圈，这是最严重的可见度问题，不能给高分。

### AUTHORITY 权威与背书

| 条件 | 区间 |
|------|:--:|
| 百科词条 + 知识面板 + ≥3 家权威媒体 | 80-95 |
| 百科词条 + 1-2 家权威媒体 | 60-79 |
| 仅有社区/UGC 内容 | 40-59 |
| 几乎无第三方覆盖 | 15-39 |

**加权参考**：百科词条与知识面板权重最高（AI 回答的主要引用源），行业榜单次之，社区 UGC 最低。

### CONTENT_ASSETS 内容资产

| 条件 | 区间 |
|------|:--:|
| 5 类内容齐全，且近 3 个月有更新 | 80-95 |
| 3-4 类内容，近半年有更新 | 60-79 |
| 1-2 类内容 | 40-59 |
| 内容严重缺失或长期未更新 | 15-39 |

五类内容：产品详情页 / FAQ 帮助中心 / 参数规格页 / 评测案例 / 博客长文

### STRUCTURE_MARKUP 结构化与标记

| 条件 | 区间 |
|------|:--:|
| 6 项检测全通过 | 90-100 |
| 通过 4-5 项 | 70-89 |
| 通过 2-3 项 | 45-69 |
| 通过 0-1 项 | 10-44 |

六项检测：JSON-LD 结构化数据 / 表格化参数 / QA 区块 / 语义化标题层级 / meta 与 OG 标签 / 可摘录的结论性段落

### SENTIMENT 舆情健康

| 条件 | 区间 |
|------|:--:|
| 负面率 < 0.10 | 85-100 |
| 负面率 < 0.20 | 70-84 |
| 负面率 < 0.35 | 50-69 |
| 负面率 ≥ 0.35 | 20-49 |

**修正**：存在 high severity 议题且无官方内容承接时，下调 5-10 分。

### COMPETITIVE 竞争位势

| 条件 | 区间 |
|------|:--:|
| 声量份额居首 | 85-95 |
| 份额 ≥ 竞品均值 | 65-84 |
| 份额 < 竞品均值 | 40-64 |
| 显著落后（不足首名 30%） | 15-39 |

## 输出前自检清单

逐项检查，全部打勾才能进入渲染：

- [ ] 六个维度齐全，code 与 `schema.js` 完全一致
- [ ] `totalScore` = Σ(score × weight)，误差 ≤ 1.5
- [ ] 每个维度的 `evidenceCoverage` 三项合计 = 1
- [ ] 每个维度的 `comment` 都引用了具体数据，没有空话
- [ ] `SENTIMENT.distribution` 三项合计 = 100
- [ ] 每条 action 的 `dimension` 是六维 code 之一
- [ ] 每条 action 的 `expectedGain` ≤ 8，累计 ≤ 30
- [ ] 每条 action 的 `description` 引用了前序阶段的具体数据
- [ ] 每条 action 的 `nextSteps` 是可直接执行的动作，不是原则
- [ ] `SIMULATION.note` 含"不参与总分计算"
- [ ] L1/L2 条目都有 sources 且带 url；L3 条目都有 note
- [ ] 没有把 L3 数据当作已验证事实陈述
- [ ] 缺失数据已标注，没有用推理值填充数量字段

## 反模式

| ❌ 反模式 | ✅ 正确做法 |
|----------|-----------|
| "品牌 GEO 表现较差" | "检索可见度 42 分：9 条查询命中 3 条，且全部来自含品牌词的查询" |
| "建议加强内容建设" | "[P0] 为 6 个产品页补齐 Product JSON-LD → 预期 +7 分，1-2 周" |
| "品牌在市场上有一定知名度" | "声量份额 7%，居第 5 位，为首名凯迪仕（31%）的 23%" |
| 用推理值填补 count / mentions 等数量字段 | 抓不到就记 0 或 null，标注 L3 |
| "结构化数据表现一般" | "6 项检测通过 2 项：标题层级与 meta 标签通过；JSON-LD、表格参数、QA 区块未通过" |
| 只说问题不给方案 | 每个风险至少配一条 action |
| 给所有品牌差不多的分数 | 严格按锚定表，允许分数难看 |
| 报告的分数很好看但建议很空 | 分数与建议必须能互相印证 |

## 执行摘要撰写规范（金字塔原理）

| 组成 | 要求 | 反例 |
|------|------|------|
| `headline` | 一句话最大判断，60 字内，有观点有数据 | ❌"本报告对云澈品牌的 GEO 表现进行了全面评估" |
| | | ✅"品牌只在用户已经认识它时才被找到——决策前期的流量全部流向竞品" |
| `judgments` | 恰好 3 条，按重要性降序，每条是判断不是数据 | ❌"检索可见度得分 42 分，处于一般水平" |
| | | ✅"6 条品类通用查询 0 命中，意味着所有新增需求都不会想到这个品牌" |
| `biggestOpportunity` | 投入产出比最高的 1 个，不是最大的问题 | ❌把"检索可见度低"当机会点（那是问题不是机会） |
| | | ✅"补齐 6 个产品页的 JSON-LD，2 周可完成，预期 +7 分" |

**判断 vs 数据的分界**：数据是可以被验证的事实，判断是你从事实里得出的结论。
执行摘要要的是后者，但每条判断后面必须挂得住证据。

## 分维度行业基准（三级来源）

基准线是报告里最容易造假的地方——因为它看起来像有据可依，一旦是编的，整份报告的可信度会被连带拉垮。所以本 skill **不允许 AI 凭空估算行业平均水平**。

### 三级来源，按优先级取用

| 级别 | source | 怎么来的 | 报告呈现 |
|:--:|---|---|---|
| 1 | `measured` | 竞品同口径实测：对 Top2-3 竞品用**完全相同的方法**测各维度 | 红色**实线**，标注样本量 |
| 2 | `accumulated` | 本地累积：同品类 ≥3 个品牌的历史审计维度分均值 | 红色**长虚线**，标注样本量 |
| 3 | `preset` | 用户在 `references/benchmarks.json` 配置的真实行业数据 | 红色**短虚线** |
| — | 都不可用 | — | **不画基准线**，图注注明"暂无可用的分维度行业基准" |

### 硬性规则

- **每个基准维度必须挂 evidence**——无证据的维度会被静默丢弃
- **至少 2 个维度有值**才画线；只有 1 个维度没有意义
- **缺失的轴不闭合**——画开放折线，绝不用其他维度的均值去补位
- **累积基准要求 ≥3 个不同品牌**——同品牌多次审计只取最新一条，防止单一品牌刷权重
- 累积库在 `diag-output/.benchmarks/<品类>.jsonl`，`--no-record` 可关闭记录

### 为什么不让 AI 估

| 做法 | 问题 |
|---|---|
| ❌ AI 生成"检索可见度行业基准 65 分" | 无法核查、无法复现；读者会以为有据可依，实际是幻觉 |
| ❌ 用缺失维度的均值补齐六个轴 | 制造了"全维度都有基准"的假象 |
| ✅ 竞品实测 + 证据 | 同品类、同口径、同一次采集，是最硬的基准 |
| ✅ 累积 ≥3 个品牌 | 随使用自然增长，样本量透明披露 |
| ✅ 无基准就留白 | 诚实。一次诚实的"暂无"胜过六个编造的数字 |

## 根因分析撰写规范

### 三段式

| 层 | 回答什么问题 | 特征 |
|---|---|---|
| 现象 `symptom` | 观测到了什么？ | 可量化、可复现，带数字 |
| 直接原因 `directCause` | 表面上为什么会这样？ | 第一层解释，通常指向某个具体缺失 |
| 根本原因 `rootCause` | 为什么会缺失？源头是什么？ | **必须指向一个可以被改变的动作** |

### 判定标准：挖够了没有

问自己：**这个根因能不能直接写出一条整改措施？**

- 能 → 挖到位了
- 不能，比如"行业普遍如此""品牌体量所限"→ 还没挖够，继续往下挖一层

### 禁止的万能答案

| ❌ 万能答案 | 为什么不合格 | ✅ 应该挖到 |
|---|---|---|
| 不重视 | 是态度描述，不可观测也不可改变 | 谁不重视？体现在哪个流程缺失？ |
| 投入不足 | 是结果 | 具体缺什么资源？缺哪个环节的人？ |
| 意识不够 | 无法验证 | 哪个决策体现了意识缺失？ |
| 缺乏战略 | 太抽象 | 缺哪个具体的内容/技术布局？ |
| 团队能力有限 | 不可改变（至少短期内） | 能力短板具体在哪一项？能否外包/培训？ |

### 证据要求

`rootCause.evidence` **必填**。没有证据可挂就不要写 rootCause——
宁可让某一维没有根因分析，也不要编一个看起来合理的解释。

这是全套 skill 的核心防线：数据层不许编造，分析层同样不许。

## 常见误判

| 误判 | 问题 | 正确做法 |
|------|------|---------|
| 品牌词排名好 → 可见度高 | 混淆了"被搜索"与"被发现" | 必须分开统计品牌词查询与通用词查询的命中率 |
| 官网内容多 → 内容资产分高 | 忽略可引用性 | 数量只是 CONTENT_ASSETS 的一半，另一半看新鲜度；可引用性由 STRUCTURE_MARKUP 单独衡量 |
| 没有负面 → 舆情健康分高 | 可能只是没搜到 | 舆情扫描覆盖不足时，evidenceCoverage 的 L3 会拉低置信度 |
| 竞品很多很强 → 竞争位势分低 | 用印象代替统计 | shareOfVoice 必须是真实提及次数统计 |
| L1 覆盖低但分数高 | 分数建立在推演上 | 置信度会暴露这一点；正式交付应走 deep 档 |

## 模型适配

| 模型系列 | JSON 可靠性 | 适配要点 |
|---------|:--:|---------|
| GPT-4o / o1 | 高 | 原生支持，无需特殊处理 |
| Claude 3.5+ | 高 | 偶尔包裹代码块，需 strip |
| Gemini 2.0+ | 中 | 倾向在 JSON 前后加解释文字，需截取 |
| DeepSeek V3 | 中 | 偶尔输出不完整 JSON，需重试 |
| Qwen 2.5+ | 中高 | 长 JSON 可能截断，建议分阶段写 |

**JSON 提取规则**：
1. 直接 `JSON.parse(输出)`
2. 失败则取第一个 `{` 到最后一个 `}` 之间
3. 仍失败则 strip 代码块标记后重试
4. 最终失败则重试该阶段（最多 1 次）
