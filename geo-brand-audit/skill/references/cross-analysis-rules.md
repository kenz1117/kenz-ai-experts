# 多源交叉分析规则

阶段5（社媒 + 热搜）采集完成后，`merge-stages.js` 会自动调用 `scripts/lib/cross_analysis.js`
计算交叉层，结果写入 `report.cross`。**本文件说明它的口径与边界。**

---

## 为什么需要这一层

六维评分回答的是「品牌的检索资产怎么样」。但单独看六维，看不出三件事：

1. 品牌对外呈现的叙事，和用户真实讨论是不是一回事
2. 品牌在检索 / 社媒 / 热搜三个场景下的相对位置
3. 有没有哪个渠道已经在冒烟

交叉层就是把这三个真实信号源对齐，回答上述问题。

---

## 铁律（不可协商）

| # | 规则 | 违反后果 |
|:--:|---|---|
| 1 | **只吃真实数据** —— SOCIAL / HOTSEARCH 每条样本都已在 schema 强制挂证据 | 校验器报错 |
| 2 | **缺数据就是 `null`，不补 0、不估算** | 报告显示"未采集" |
| 3 | **归一化公式全部公开**，人工可复算 | 无黑箱 |
| 4 | **"未采集" ≠ "采集过、确认为 0"** —— 前者 null，后者 0 | 两者语义必须区分 |

> 第 4 条最容易被忽略。品牌**确认没上热搜**是事实（`hotIndex = 0`）；
> 品牌**没查热搜**是缺数据（`hotIndex = null`）。这两者在报告里必须长得不一样。

## 指标定义

### 1. 叙事鸿沟 Narrative Gap

```
情绪分   = 正面% − 负面%          区间 −100 ~ +100（中性不计入）
叙事鸿沟 = 检索叙事情绪 − 社媒口碑情绪
```

| 鸿沟值 | 判定 | 含义 |
|---|:--:|---|
| ≥ +20 | 叙事虚高 | 公开叙事明显好于社媒真实口碑 —— 高危错位，口碑已在埋雷 |
| −20 ~ +20 | 叙事一致 | 两侧情绪基本一致，无显著错位 |
| ≤ −20 | 叙事低估 | 社媒口碑好于检索叙事 —— 真实好评没被检索侧接住，GEO 机会 |
| 无法计算 | 数据不足 | 缺少任一源的情绪分布 |

**为什么"虚高"是危险的**：检索叙事反映的是品牌对外能被搜到的内容（官网、媒体稿、百科），
社媒反映的是用户真实体验。两者背离越大，说明品牌在用内容覆盖问题，而不是解决问题。

### 2. 三源可见度矩阵

| 信号源 | 计算方式 | 量纲 | 高/低分界 |
|---|---|---|:--:|
| 检索可见度 | 直接取报告总分 `totalScore` | 0-100 质量分 | **60**（对齐报告"一般"评级线） |
| 社媒声量 | `log10(1+总互动) / log10(1+100000) × 100` | 对数归一化的声量档位 | 50 |
| 热搜热度 | `log10(1+最高热度) / log10(1+1000000) × 100` | 对数归一化的热度档位 | 50 |

**为什么分界不同**：检索可见度是质量分，社媒/热搜是声量档位，量纲不同。
用同一把尺子比，会把「质量 54 分但声量很高」误判成"全面领先"。

声量档位：

| 区间 | 社媒 | 热搜 |
|---|---|---|
| 75-100 | 高热 | 爆榜 |
| 50-74 | 活跃 | 在榜 |
| 25-49 | 低迷 | — |
| 1-24 | 沉寂 | 偶发 |
| 0 | — | 未上榜 |

**象限落点**（需至少 2 个源有数据）：

| 象限 | 条件 | 含义 |
|---|---|---|
| 全面领先 | 各源均高 | 保持并放大优势 |
| **有热度无资产** | 检索低 +（社媒高 或 热搜高） | 用户已经在聊，但检索侧接不住 —— **GEO 最大机会** |
| 有资产无热度 | 检索高 +（社媒低 或 热搜低） | 检索资产尚可，缺真实讨论 —— 补内容分发 |
| 双弱待启动 | 各源均低 | 需从检索资产与内容双线起步 |
| 参差 | 其余 | 各源表现不一致，逐源定位 |

### 3. 危机三通道

| 通道 | 数据源 | 强度计算 | 触发线 |
|---|---|---|:--:|
| 检索舆情 | `SENTIMENT` | `负面率 × 200`（50% 打满）；`riskLevel=high` 保底 70 | ≥40 或 riskLevel=high |
| 社媒口碑 | `SOCIAL` | `负面率 × 200`；负面帖互动占比 ≥ 其数量占比 1.5 倍时 +15 | ≥40 |
| 热搜信号 | `HOTSEARCH` | 上榜且关联负面 = 75；仅上榜 = 20 | ≥40 |

```
危机评分 = min(100, 最高通道强度 + (触发通道数 − 1) × 10)
```

**任一通道触发即预警**，不要求三通道齐亮。

- `confidence` = 有数据的通道数 / 3。只有 1 个通道有数据时，评分可信度 33%，
  报告会显式标注 —— 这不是保守，这是诚实。
- 社媒样本 < 10 条时，通道判读会追加"样本噪声较大"提示。

### 4. 竞品多维并集

合并两个来源的竞品：

- **检索声量榜**（`COMPETITIVE.shareOfVoice`）
- **社媒讨论共现**（`SOCIAL.competitorsMentioned`）

再标注每个竞品是否出现在热搜条目标题中。按「覆盖源数量」降序排列 ——
覆盖源越多，说明该竞品在越多场景下与你正面竞争。

## 已知局限（必须向读者披露）

1. **声量/热度是相对值**，用于横向对比，不代表绝对市场份额。
2. **对数归一化的天花板是人为设定的**（社媒 10 万互动 / 热搜 100 万热度打满），
   定义在 `cross_analysis.js` 的 `NORM` 中，可按品类调整，但必须连同报告一起说明。
3. **社媒样本量通常偏小**，负面率的统计噪声较大；样本 < 10 条时报告会提示。
4. **热搜竞品识别是标题字符串匹配**，可能有误匹配或漏匹配，仅作线索不作品结论。
5. **只覆盖中国平台**，无海外视角。
6. **情绪判定来自 Agent 对标题/正文的判读**，不是平台官方数据；
   判读依据保留在样本表的证据列，可逐条复核。

## 改动指标口径的正确姿势

所有阈值集中在 `cross_analysis.js` 顶部：

```js
var NORM = { socialCeiling: 100000, hotCeiling: 1000000 };
var TH   = { quad: 50, gap: 20, crisis: 40, negRate: 0.25, minSocialPosts: 10 };
var QUAD_THRESHOLD_BY_SOURCE = { visibility: 60, social: 50, hotsearch: 50 };
```

改这里即可，**不要散落在计算逻辑里**。改完务必重跑：

```bash
node scripts/merge-stages.js diag-output --no-record
node scripts/build-report.js <merged.json>
```
