# 检索执行手册

---

## 分档采集

| 档位 | 触发说法 | WebSearch | WebFetch / curl | TopN 核验 | 并发 | 目标耗时 |
|------|---------|:--:|:--:|:--:|:--:|:--:|
| `quick` | "快速看下"、"摸个底" | ✅ | ❌ | 5 | 1 | 2-3 min |
| `standard` | 默认 | ✅ | 抽样 | 10 | 3 | 5-8 min |
| `deep` | "出正式报告"、"要交付" | ✅ | 逐条 | 20 | 3 | 15-25 min |

**standard 档的抽样范围**：官网首页、一个代表性产品页、百科词条、权威媒体 Top3。
**deep 档**在此基础上扩展到全部产品页、全部权威来源、Top10 检索结果。

---

## 查询词矩阵设计

阶段 1 生成的 `queryMatrix` 是阶段 3 的唯一输入，设计要点：

| intent 分组 | 示例 | 作用 |
|------------|------|------|
| 选购推荐 | "智能门锁 推荐 2026"、"3000 元门锁 哪款好" | 检验高意图流量是否触达 |
| 品牌评测 | "云澈门锁 怎么样" | 检验品牌词占位 |
| 竞品对比 | "云澈和凯迪仕 哪个好" | 检验对比场景中的呈现 |
| 售后与痛点 | "门锁 电池 续航"、"XX 售后 维修" | 检验负面议题与内容缺口 |

**关键约束**：无品牌词的通用查询不少于总条数的一半。
只在品牌词查询里命中 = 品牌没有破圈，这是最常见也最严重的可见度问题。

## 并行策略

```
阶段1（串行，产出查询词矩阵与竞品集）
   ↓
┌──────────────┴──────────────┐
阶段2 采资产              阶段3 测可见 + 扫舆情
（WebFetch/curl 组）      （WebSearch 组）
└──────────────┬──────────────┘
               ↓
          阶段4 评分
```

- 同组检索**同时发起**，不设间隔
- curl 抓取并发上限 3（deep 档同样），避免被判定为攻击
- 网页抓取失败不影响其他条目，逐项独立降级

## 竞品共现涌现

1. 搜品类通用词 6-10 次（`{品类} 推荐` / `{品类} 怎么选` / `{品类} 排行榜` / `{品类} 十大品牌` / `{品类} 测评`）
2. 提取每条结果的正文/摘要中出现的品牌名
3. **过滤**：广告位、导航、侧边栏、聚合站的堆砌式罗列、导购页的品牌墙
4. 按共现频次降序取 Top5
5. 用户指定的竞品强制入榜，`origin="user"`

**噪声处理**：
- 只出现 1 次的品牌不入选（可能是偶然提及）
- 聚合站（如"XX 大全"类页面）的品牌列表整体降权
- 若某个"品牌"其实是品类词或型号词，剔除

---

## 声量份额统计

在阶段 3 的全部检索结果中统计：

```
某品牌 share = 该品牌提及次数 / 全部品牌提及总次数
```

- 只统计正文中自然出现的品牌名
- 排除仅出现在导航、侧边栏、广告位、面包屑中的品牌
- 本品牌与竞品用同一口径统计，不做任何加权

## 缓存

对同一品牌 + 品类的重复审计，缓存检索结果避免重复请求。

| 缓存类型 | 路径 | TTL |
|---------|------|-----|
| 竞品共现 | `diag-output/.cache/competitor.json` | 7 天 |
| 权威背书 | `diag-output/.cache/authority.json` | 7 天 |
| 检索可见度 | `diag-output/.cache/visibility.json` | 1 天 |
| 舆情 | `diag-output/.cache/sentiment.json` | 1 天 |

```json
{
  "cachedAt": "2026-08-29T11:00:00+08:00",
  "brand": "云澈",
  "category": "智能门锁",
  "type": "competitor",
  "results": [ { "query": "...", "items": [] } ]
}
```

命中判断：检查文件是否存在 → 读 `cachedAt` → 未过期直接用，过期则重采并覆盖。
**注意**：缓存命中时，`fetchedAt` 保持原值，不要改成当前时间——否则会伪造证据新鲜度。

## 重试与容错

| 异常 | 处理 |
|------|------|
| 检索超时 / 无结果 | 换查询词重试 1 次；仍无结果则记为未命中（L3） |
| 结果不相关 | 扩大或收窄查询词，重试 1 次 |
| WebSearch 完全不可用 | 全部依赖检索的维度降级 L3，报告中标注"检索工具不可用" |
| curl 返回 403 / 429 | 换 UA 重试 1 次；仍失败则降级并在 `fetchNote` 写明 |
| 页面需 JS 渲染 | 标注 L3，note 写"页面需 JS 渲染，静态抓取无内容" |
| WebFetch 超时 | 降级 L2（若搜索结果可用）或 L3 |

## 结果验证

- **URL 格式**：必须以 `http(s)://` 开头
- **相关性**：结果标题或摘要需含品牌词、产品词或竞品词
- **去重**：同一 URL 只保留一条
- **时效性**：优先近 1 年内容，明显过期的标注时间

## 数据源优先级

| 目标 | 首选 | 备选 |
|------|------|------|
| 百科词条 | 百度百科 / 维基百科 | 搜狗百科、头条百科 |
| 知识面板 | 直接搜品牌名的搜索结果首屏 | — |
| 权威媒体 | 行业垂直媒体 | 综合门户的科技/消费频道 |
| 社区 UGC | 知乎、小红书、什么值得买 | 垂直论坛 |
| 行业榜单 | 行业协会、垂直媒体的年度榜单 | 第三方咨询报告 |

## 一句话原则

**抓得到才算数，抓不到就说实话。** 一次诚实的"数据缺失"，比十个编造的漂亮数字更有价值。
