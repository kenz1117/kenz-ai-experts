# 离线样本夹具

`sample-audit.json` 是一次完整审计的合并结果快照，**包含阶段5（SOCIAL + HOTSEARCH）**。

## ⚠️ 关于这份数据的性质

> **这是样例数据，不是真实审计结果。**
> 品牌名（示例海洋馆）、竞品名（对照竞品馆）与**全部 URL 均已替换为占位符**
> （统一指向 `example.com`），仅用于验证渲染与回归测试。
>
> 请不要把它当作任何真实品牌的证据引用，也不要直接照抄其中的 URL。

之所以要脱敏：本 skill 的全部价值建立在「证据可核查」上。一份看起来像真实审计、
实则含虚构 URL 的样本，会直接违背这个原则。品牌名也一并虚构，避免把测试数据
误挂到真实企业名下。

## 用途

让 `build-report.js` / `build-markdown.js` **脱离任何活 API** 直接渲染，
从而在改动脚本或模板后立刻验证输出没被破坏。

## 一键回归

```bash
node scripts/smoke-test.js
```

覆盖 5 组、39 条断言：

| 组 | 验什么 |
|:--:|---|
| 1 | 合并报告通过 schema 校验 |
| 2 | 交叉分析「有阶段5」路径（叙事鸿沟 / 三源矩阵 / 危机三通道 / 竞品并集） |
| 3 | 交叉分析「无阶段5」降级路径 —— 缺数据时必须是 `null`，不得补 0 或估算 |
| 4 | HTML + Markdown 渲染（含数据契约：社媒样本必须全带 url） |
| 5 | 降级渲染 —— 无阶段5 时报告仍完整，且明说「未采集」 |

退出码 `0` 全通过，`1` 有失败。加 `--keep` 保留产物到临时目录便于人工查看。

## 关于断言方式（重要）

报告是**静态注入数据 + 浏览器端 JS 渲染**：`build-report.js` 只把 JSON 塞进模板，
`#app` 初始为空，所有 DOM 在浏览器里运行时才生成。

因此静态 HTML 里：
- **永远找不到**渲染后的 `<a>` 标签（还没渲染）
- **永远能找到**模板源码里的中文串（与数据无关）

所以 `smoke-test.js` 的 DOM 相关断言一律在**数据层**做 —— 校验注入的数据契约
（`cross.available`、`posts[].url` 等），它决定了浏览器会渲染出什么。
真正看见页面需要打开 HTML：

```bash
node scripts/build-report.js output/samples/sample-audit.json /tmp/preview.html
open /tmp/preview.html
```

## 更新夹具

当数据结构新增字段、或报告模板新增章节后，应重跑一次真实审计并替换本文件，
否则夹具覆盖不到新逻辑。替换时请沿用同样的脱敏处理。
